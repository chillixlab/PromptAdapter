## 研究テーマ
- Training-FreeなPromptAdapterの開発

## 背景
- KnowNarratorは業務という単位でデータソースを管理し、RAGを行う。企業は電通総研のRAGに価値を感じてくれていて、製品として強化する価値がある機能といえる。
- KnowNarratorは顧客企業によって利用できるLLMモデルに違いがあり、全ての企業で最新のもっとも性能の良いモデルが使用できるとは限らない。
  - 例えば、H社ではGeminiを契約していない。T社ではClaudeが使用できないなど
- またモデルが増えすぎて、顧客自身がどのモデルを使用したらベストなパフォーマンスが出るか分からず、とりあえず最新のGPTを使う。みたいなこともある。
- もし使用できないモデルの中に、最も良い性能を持つモデルがある場合、顧客はKnowNarratorがもつ本来のパフォーマンスを活用できていないという課題が生じる
- 課題に対応するため、[PUMA](https://www.arxiv.org/abs/2601.12034)のようなモデル自体のFine-TuningをKnowNarratorで行うにはコストがかかるため現実的な解決策ではない。
- そこで、もっとも性能の良いLLMモデルに近い振る舞いを可能とするようなシステムプロンプトを作成する手法:PromptAdapterを提案し、Training Freeに上記課題を解決する。

## 提案
- PromptAdapterを構築し、LLMのRAGにおける性能をTraining-Freeで向上させる
- 具体的には、RAGにおけるベスト（recall,precision,tool_callの回数など定義した指標）なクエリ生成（と推論）を可能にする

### STEP1 トップモデル$M^*$の選定
1. 用意したAllganizeデータを用いて複数のLLMモデル $\mathbb{M_i} = \{ M_1,M_2,...M_I \}$に対し、RAGを用いた回答生成を実行する
   - RAGの前処理はKNSや自前実装でも問わない。実験の設定として埋め込みモデル、チャンクサイズ、オーバーラップサイズが管理出来れいればよい。
  
2. 得られた$M_i$に対し、RAGASによる評価を実行
   - RAGAS : https://arxiv.org/abs/2309.15217
   - ライブラリ：https://docs.ragas.io/en/stable/
   - 評価指標は以下 : 検索と推論の両方で評価する
     - ContextRecall（コンテキストの再現率）
       - 引数：Ground Truth Answer, Context
     - ContextPrecision（コンテキストの精度）
       - 引数：Query, Context
     - Faithfulness（忠実度）
       - 引数：Response, Context
     - Answer Relevancy（回答の関連性）
       - 引数：Query, Response
   - スコア範囲は[0.0~1.0]で高いほど良い。
   - 得られる結果イメージ   
        ```
        model        recall  precision  faithfulness  relevancy
        gpt-4o       0.90    0.80       0.88          0.91
        gpt-4.1      0.87    0.85       0.92          0.89
        gemini-2.5   0.92    0.70       0.80          0.90
        ...
        ```

3. パレート最適集合を作成し、その後トップモデル$M^*$を決定する
   - 上記の指標はモデルごとに各指標のトレードオフな状態が発生すると考えられる。（この値はgemini強いけど、こっちはgpt強いなど）
   - パレート最適集合$\mathbb{M^{pareto}}$ をいったん作り、下位モデルを振るい落とす。（実装は自前で作る）
   - その後、$\mathbb{M^{pareto}}$の中でContext Recallが最も高いモデルを$M^*$として決定
     - なぜContext Recallなのか？
     - →RAGを組み込んだ実システムを考えるうえで、回答生成の為に必要な情報がデータソースから獲得できないことが一番課題になる。そこで今回はContext Recallが良い＝いい検索が出来ているという前提を置いてトップモデルを決定する
  
## STEP2 トップモデル$M^*$をターゲットにしたPromptAdapterの設計
1. 各データに対する$\delta = Score(M^*)- Score(M_i)$を計算する  
   - 得られる結果イメージ
   - 例:$M^*$=GPT5.2, $M_i$=GPT-4o   
        ```
        model        Δrecall  Δprecision  Δfaithfulness　Δrelevancy
        gpt-4o       -0.10      -0.05       -0.06          -0.10
        gpt-4o       -0.10      -0.15       -0.06          -0.10
        gpt-4o       -0.13      -0.01       -0.03          -0.10
        ...
        ```
2. 結果をK-meansでクラスタリング(K=4)
  - K=4の理由は測定軸が4つなので、各軸ごとに最低限測定できればOK
  - 今後拡張の余地あり

3. 各クラスタ$C_i$の平均Δを算出
  
        ```
        cluster        Δrecall  Δprecision  Δfaithfulness　Δrelevancy
        C1(nc1=40)       -0.10      -0.05       -0.06          -0.10
        C2(nc1=20)       -0.10      -0.15       -0.06          -0.10
        C3       -0.13      -0.01       -0.03          -0.10
        ...
        ```
      
4. $C_i$の重みWeightとクラスタの大きさを示すL２ノルムを算出し、優先的にプロンプトに反映する指標となる$Impact$を計算する
   - $W_c = {n_c \over N} = {クラスタCに属するノード数 \over 全体ノード数(データセットの全体数)}$
     - 例：$W_1 = {40 \over 100} = 0.4$
   - $\| \mu_c \|$ = $\sqrt{\sum_{i} (\mu_c,i)^2}$ = $\sqrt{各クラスタの４つの指標の平均値の２乗}$
     - 例：$\mu_{C_1}$ = $\sqrt{(0.10)^2+(0.05)^2+(0.06)^2+(0.10)^2} ≒ 0.xx$
 - $Impact = W_c * \| \mu_c \|$
 - このImpact指数が大きいクラスタの特徴から優先的にプロンプトで振る舞いを調整したい。
 - やりたいことは、最も多い、良くない振る舞い（検索の再現率が低いとか）をただすようなプロンプトに落とし込むこと。
 - **※LLMに全部突っ込んでプロンプト考えさせることもできるが、それをやってしまうと全てがメタプロンプティングするLLM依存になってしまうので、なるべくプロンプトを作る直前までアルゴリズム的に作りたい。**
5. LLMにプロンプトを作らせる
   - WIPだがある程度固まってきた
   - 上記のインパクト指数とかを入力にして、単に言語化してもらうだけの写像関数として振舞わせることで再現性の低いLLM依存だと思わせるのを脱したい。仕組化することで汎用的に使えるんですよと言えたらベスト。
